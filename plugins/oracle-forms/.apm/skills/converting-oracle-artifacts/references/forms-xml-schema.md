# The Forms XML schema: what it is, where it came from, how to refresh it

## What it is

`forms-14c.xsd` is **Oracle's own** XML Schema for Forms 14.1.2 XML (`Forms2XML` output and `XML2Forms` input). Its header reads "Oracle Forms 14.1.2 Forms XML Schema Definition File, Copyright(c) 2001, 2024, Oracle and/or its affiliates"; target namespace `http://xmlns.oracle.com/Forms`; 168,694 bytes; root element `Module`, which holds a `FormModule`, `MenuModule`, or `ObjectLibrary`. We did not write it.

## Where it lives (an asset, not a reference)

The schema is an **asset**: a data file that scripts read. Agents should not read it whole (about 168 KB); search it for an element or attribute name. The references are this page and `compiling-and-running-oracle-forms/references/xml-validation.md`.

| Copy | Owner |
|---|---|
| `converting-oracle-artifacts/assets/forms-14c.xsd` | this skill; `extract_forms_schema.py` compares and updates it |
| `compiling-and-running-oracle-forms/assets/forms-14c.xsd` | used by `validate_forms_xml.py` (skills are packaged self-contained) |

Both are byte-identical (no copy in `docs/`) (SHA-256 `57b113f4...`). Also in `assets/` of both skills: `reports.dtd`, Oracle Reports' DTD, copied from the 14c Oracle Home (`reports/dtd/reports.dtd`, 56,240 bytes). Reports XML is validated against that DTD; it has no XSD.

## Provenance

The committed schema was added on the macOS setup (commit `4e461e0`, 2026-11-09). **How it was obtained is not recorded**: no document says whether it was generated by Oracle's schema generator or copied from the Oracle Home. That is what `extract_forms_schema.py` settles.

## Extracting it from the installed Oracle Forms

Oracle 14c does **not** have `forms/util/getformsxmlschema.sh` (no such file exists in this Oracle Home). The schema generator is the Java class `oracle.forms.util.xmltools.SchemaGenerator` in `jlib/frmxmltools.jar`. The template `forms/templates/scripts/frmxmlsg.sh` ("Oracle Forms XML Schema Generator") wraps it, and `frmxmlv.sh` wraps Oracle's own validator, `oracle.forms.util.xmltools.XMLValidator`. Like the other 14c batch scripts they are unfilled templates (`%ORACLE_HOME%`), so the skill runs the class directly with the Forms2XML classpath (`frmjdapi.jar:frmxmltools.jar:xmlparserv2.jar`).

```bash
python3 plugins/oracle-forms/.apm/skills/converting-oracle-artifacts/scripts/extract_forms_schema.py            # extract and compare
python3 plugins/oracle-forms/.apm/skills/converting-oracle-artifacts/scripts/extract_forms_schema.py --usage    # the generator's own usage text
python3 plugins/oracle-forms/.apm/skills/converting-oracle-artifacts/scripts/extract_forms_schema.py --update   # refresh both copies
```

It runs in a throwaway `forms-converter-14c` container (Podman must be running; on Windows run it from the Ubuntu WSL shell), takes the schema from stdout or a `.xsd` file in `temp/forms-schema/<version>/`, and reports IDENTICAL or DIFFERENT against the committed copy. Nothing is changed without `--update`.

**Status: not verified.** The script was written from the Oracle template and class names while the Podman runtime was down. The generator's command-line arguments were not checked, so the first run may need `--usage` and `--generator-args`. Do not describe the committed schema as "confirmed against this install" until the script has reported IDENTICAL.

## Adding another version (for example 12c)

Point the script at that version's Oracle Home and name it: `extract_forms_schema.py --version 12c --oracle-home oracle-reference-stack/oracle_home --update` (the 12c image is `forms-converter:latest`; set `OFW_CONVERTER_IMAGE=forms-converter:latest` first). `validate_forms_xml.py --version 12c` then uses the saved schema file `forms-12c.xsd` in the skill's assets folder. The 12c Oracle Home exists only on the Mac setup, so this is **not verified** here.

## What the schema does and does not catch

It catches wrong element and attribute names, wrong types (for example the dotted `version`), and illegal content. It does not check meaning: the Module `version` only has to be a number (`xs:long`), so a 12c number passes; Oracle can still reject a file that is schema-valid (for example off-canvas geometry or missing database objects). A pass is "schema-valid", not "will compile".
