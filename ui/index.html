Dependency checklist

    Setup and server startup instructions
    1. Install Python 3, Podman, and a Java runtime compatible with your Forms 14c installation. This project's reference launcher expects Java 17 or newer. Check with python3 --version, podman --version, and java -version.
    2. First-time setup: provision the Oracle Database Free and Forms 14c testbed using oracle-reference-stack/README.md and docs/FORMS-AND-REPORTS-14C-TESTING-GUIDE.md. Forms installers must be obtained from Oracle under the applicable licence; the Rust app does not include them. The configured domain must deploy formsapp to AdminServer and provide the FREEPDB1 alias.
    3. For an existing installation, start the Podman machine if your platform uses one, then start both containers from a terminal on the server computer:
    podman machine start
podman start oracle23ai-lite
podman start forms-server-14c

    Skip podman machine start on native Linux or when the machine is already running. “Container not found” means first-time testbed setup is still required. Starting containers alone does not install or configure Oracle.

    The configured Forms container starts WebLogic automatically. Allow it time to boot, then check:

    podman logs --tail 80 forms-server-14c
curl -I http://localhost:7001/forms/frmservlet
python3 plugins/oracle-forms/.apm/skills/setting-up-oracle-testbed/scripts/health_check.py

    Run commands from the repository root. The expected FSAL client is oracle-reference-stack/oracle_home_14c/forms/java/frmsal.jar. Missing files require completing the reference installation; do not download an arbitrary JAR.

    For the native viewer itself, run cargo run -p oracle-forms-server, then open http://127.0.0.1:7070. The preview compile-connection fields supply compiler credentials; the Oracle desktop window prompts separately. Testbed usernames/passwords and tables must already exist.
